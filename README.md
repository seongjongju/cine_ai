# Cine AI

> **Gemini 2.5 Flash 기반의 AI 대화형 맞춤형 영화 큐레이션 플랫폼**  
> TMDB의 영화 데이터와 Gemini API를 결합하여, 사용자가 선택한 모드에 따라 영화에 대한 깊이 있는 분석과 인사이트를 맞춤형으로 제공하는 모바일/웹 서비스입니다.
> 서비스 URL: https://cine-ai-murex.vercel.app/
> GitHub 저장소: https://github.com/seongjongju/cine_ai

---

## 1. 프로젝트 소개
* **프로젝트 이름**: Cine AI
* **개발 형태**: 1인 개발 (개인 프로젝트)
* **서비스 한 줄 요약**: 넷플릭스 스타일의 세련된 UI에 Gemini 2.5 Flash 엔진을 탑재하여, 사용자가 원하는 다양한 모드로 영화에 대해 질문하고 정밀한 답변을 받아볼 수 있는 스마트 영화 플랫폼입니다.

---

## 2. 핵심 기능

### AI 대화 및 영화 큐레이션
* **다양한 AI 모드 제공**: 사용자의 목적에 따라 스포일러 없이, 영화광 스타일, 철학적 해석, 친근한 대화 모드 등 원하는 관점으로 AI에게 질문할 수 있습니다.
* **맞춤형 답변 엔진**: Gemini 2.5 Flash 버전을 도입하여 빠르게 영화 관련 인사이트를 제공합니다.

### 영화 데이터 연동 (TMDB API)
* **실시간 영화 데이터**: TMDB API를 활용해 최신 개봉작, 인기작, 상영 예정작 등 다양한 영화 리스트를 실시간으로 업데이트합니다.
* **상세 정보 시각화**: 영화별 포스터, 줄거리, 평점, 장르 등 메타데이터를 직관적으로 확인할 수 있습니다.

### 사용자 경험 및 편의 기능
* **간편 소셜 로그인**: Supabase Auth를 연동해 구글 및 카카오 소셜 로그인을 통한 빠르고 안전한 인증 시스템을 구축했습니다.
* **최근 본 영화 히스토리**: 조회한 영화 기록을 저장하여 서비스 재접근성을 높였습니다.
* **관심 영화 찜하기 (낙관적 업데이트 적용)**: 영화 상세 페이지에서 반응 속도 지연 없이 즉시 찜 상태가 반영되도록 UI 상태를 선제적 변경하며, 마이페이지 및 위시리스트에서 관리할 수 있습니다.
* **영화명 및 장르 검색**: 대용량 영화 데이터 속에서 원하는 영화를 빠르게 찾을 수 있도록 키워드 및 장르 필터 검색을 제공합니다.

## 4. 핵심 기술적 의도 및 데이터 구조 고민

### 1. TanStack Query를 활용한 '찜하기' 낙관적 업데이트(Optimistic Updates)
영화 상세페이지에서 사용자가 '찜하기' 버튼을 누를 때 네트워크 요청 완료를 기다린 후 UI를 바꾸면 수백 밀리초 이상의 반박자 늦은 반응이 발생해 사용성이 떨어졌습니다. 이를 개선하기 위해 TanStack Query의 `onMutate` 개입 시점을 활용했습니다. 서버 응답이 오기 전 클라이언트 캐시 데이터를 즉시 수정해 찜 아이콘 상태를 바꾸고, 만약 백엔드 요청이 실패할 경우 `onError` 단에서 롤백(Rollback)시키는 낙관적 업데이트 구조를 구축해 즉각적인 인터랙션을 제공했습니다.

### 2. 사용자 목적에 맞춘 AI 프롬프트 분기 설계
최근 웹 서비스에 AI 기능 도입이 일반적인 트렌드로 자리 잡은 만큼, 단순한 일회성 질문-답변 구조를 넘어 사용자가 원하는 목적에 따라 AI 경험을 제어할 수 있도록 설계했습니다. 선택한 AI 모드(스포 방지, 영화광, 철학적 관점 등)에 맞춰 System Prompt 파라미터를 동적으로 변환하여 전달하는 방식을 도입했습니다.

## 5. 개발 과정에서 해결한 문제

### 1. 찜하기 클릭 시 네트워크 지연으로 인한 UI 반응성 저하 및 중복 클릭 에러
* **문제 상황**: 상세페이지에서 찜하기 버튼을 누를 때 네트워크 요청이 처리되는 동안 UI 반응이 없어 답답함을 유발했고, 사용자가 제대로 처리되지 않은 것으로 오인해 버튼을 여러 번 연속 클릭하며 에러가 발생하는 문제가 있었습니다.
* **원인**: 백엔드 응답이 도착한 후에만 UI를 변경하도록 비동기 흐름을 구성했던 점이 원인이었습니다.
* **해결 방법**: TanStack Query의 낙관적 업데이트(Optimistic Updates) 기술을 도입하여 서버 응답 이전에 UI를 즉시 변경하도록 개선했습니다. 이로써 사용자에게 반박자 빠른 반응성을 제공하고 중복 클릭 시도를 사전에 방지했습니다.

### 2. 위시리스트 삭제 비동기 요청 중 사용자의 중복 클릭 문제
* **문제 상황**: 위시리스트에서 영화를 삭제하는 비동기 요청이 진행되는 짧은 시간 동안, 사용자가 동일한 삭제 버튼을 다시 클릭하면서 불필요한 중복 요청이나 상태 꼬임 현상이 유발되었습니다.
* **원인**: 처리 중 상태(Loading State)에 대한 명시적인 UI 피드백과 사용자 입력 제한 로직이 없었기 때문이었습니다.
* **해결 방법**: `react-spinners` 라이브러리를 활용해 삭제 동작 진행 중임을 스피너로 암시적으로 알리고, 삭제 진행 동안에는 버튼의 `disabled` 처리나 클릭 방지 로직을 추가하여 중복 클릭을 차단했습니다.

## 6. 회고 및 향후 개선 과제

### 아쉬운 점 및 배운 점
* **사용자 피드백과 에러 핸들링의 중요성**: 단순히 네트워크 요청이 성공하는 데서 그치지 않고, 요청이 진행 중임을 사용자에게 시각적으로 알려주는 것과 실패 시 적절한 알림 메시지를 전달하는 것이 사용성에 결정적인 영향을 미친다는 점을 체감했습니다.

### 개선 및 확장 예정 사항
* **검색 필터 다변화**: 현재 제공 중인 영화명 및 장르 검색을 넘어 개봉 날짜, 감독, 출연 배우 등 다양한 조건으로 찾아볼 수 있도록 검색 필터를 확장할 예정입니다.
* **실시간 웹 서칭 기반 AI 업그레이드**: 향후 웹 서칭 기능이 지원되는 AI 모델 버전으로 업그레이드하여, 기존 제공 줄거리 이외의 외부 최신 영화 정보나 디테일한 비하인드 요소까지 답변받을 수 있도록 고도화할 계획입니다.

## 7. 프로젝트 제약 사항 및 안내

본 프로젝트는 기술 검증을 목적으로 개발되었으며, 외부 API 무료 티어 정책에 따라 다음 안내 사항이 있습니다.

* **영화 스트리밍 불가**: 영화 정보 조회 및 AI 기반 큐레이션을 제공하는 플랫폼으로, 실제 영화 영상 재생(스트리밍) 기능은 포함되어 있지 않습니다.
* **실시간 웹 서칭 제한**: Gemini 2.5 Flash API 환경 특성상 실시간 웹 서칭 기능이 제한됩니다. TMDB API를 통해 기본적으로 제공되는 영화 정보 범위 내에서 답변을 생성합니다.
* **API 호출 트래픽 제한 (RPM/RPD)**: 무료 제공 토큰 및 호출 한도를 공유하므로 동시 요청이 몰릴 경우 순간적인 생성 지연이 발생할 수 있습니다.
